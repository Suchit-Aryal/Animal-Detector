# Q&A prep (tailored to our actual results). Numbers: results/comparison.csv, results/experiments.csv.

## Model and metrics
- **Why YOLO?** Single-stage, real-time, strong pretrained weights, simple training API. Alternatives: Faster R-CNN (slower), SSD, RT-DETR. Our yolov8s runs at 78 FPS on a laptop GPU.
- **What is mAP / IoU / precision / recall?** IoU = overlap / union of predicted and true box. AP = area under the precision-recall curve per class; mAP averages classes. mAP50 counts a hit at IoU >= 0.5; mAP50-95 averages thresholds 0.5 to 0.95. Precision = correct detections / all detections; recall = correct detections / all real animals.
- **What is NMS?** Removes duplicate overlapping boxes, keeping the highest confidence (we use IoU 0.7 in evaluation).
- **What is transfer learning and freeze=10?** We start from pretrained weights. `freeze=10` keeps the first 10 layers (the generic feature extractor) fixed so only the later layers learn from our small dataset. In our runs it gave the best validation mAP50 (0.792) vs 0.663 without freezing.
- **Why yolov8s and not the bigger yolov8m?** Chosen by validation mAP50: yolov8m (0.635) was not better than yolov8s (0.663), and is 2.3x slower to train (2512 s vs 1094 s) and ~1.4x slower at inference (56 vs 78-99 FPS). Bigger models overfit more on 1247 images.
- **How did you choose the final model without touching the test set?** By validation mAP50 only. (Note: val mAP and test mAP differ a lot for unfrozen runs because both sets are small.)

## Honesty about results
- **Did you beat the baselines?** Partly. Frozen test mAP50: ours (v2) 0.842, COCO yolov8n 0.810, OIV7 yolov8m 0.906. We beat COCO on mAP50, precision (0.803 vs 0.799) and recall (0.763 vs 0.705) but not mAP50-95 (0.589 vs 0.643). The earlier v1 model scored 0.854 on the same test; the 0.012 difference is within noise for 118 boxes. COCO has no goat class, so it is evaluated on dog/cow/cat only; the comparison is not like for like.
- **Why is the OIV7 baseline so strong?** It was pretrained on Open Images V7 and our test images are Open Images, so it has probably seen similar or the same images. Its score is likely inflated; we have not verified the overlap.
- **Is the test set representative?** No: 80 Open Images images (118 boxes), not Nepali street scenes. The honest test is our own labelled street photos (still to do).
- **Why is sheep missing?** The frozen test has no sheep. After adding goat/sheep data (v2: 1066 sheep train boxes) we evaluate sheep on a separate held-out set, test_extra (80 Open Images images, 116 sheep boxes): AP50 0.711 for v2, 0.268 for the old v1 model, 0.767 for the OIV7 baseline. That set is Open Images, not street data, and small.
- **Is it overfitting?** Yes, still. Class loss train 0.38 vs val 1.02 for the v2 model (v1 freeze=10: 0.30 vs 1.09; unfrozen: 0.36 vs 1.50). More diverse data is the fix.
- **Data leakage?** Open Images images were split by image; each image is its own group, so near-duplicate frames are unlikely but not impossible. Mendeley images are train-only. Be ready to say the OIV7 overlap above is a different leakage issue.
- **Are the training labels trustworthy?** Open Images boxes are human-drawn. The 689 Mendeley images (about 55% of the training images) have boxes generated by yolov8m-oiv7 and were spot-checked on 30 images (2 rejected). Label noise is a limitation.
- **Biggest errors?** From the test set: dog labelled but predicted goat at 0.94; goats missed in a crowded scene; a cow predicted where nothing is labelled. See results/failure_cases.md. Causes are not verified.
- **Limitations?** Small data, interim non-Nepal test, night/occlusion not tested, 4 effective classes, small test set.
- **How to improve?** Label our own Nepal street photos, more goat/sheep/night images, background (no-animal) images, tracking across frames, a larger model once there is more data.

## Surveillance website
- **How do you tell people from animals?** A second model (COCO yolov8n, class `person`) runs on each frame. People are shown separately and never logged as animals. An animal box that overlaps a person box (IoU above 0.3, or mostly contained, 0.7) is dropped, unless the animal confidence is very high (override 0.8). This stops a person being logged as a dog or goat.
- **What thresholds does it use?** Animal confidence 0.5, person confidence 0.25, per-class overrides supported (currently empty). Higher animal confidence = fewer false alarms but more misses. The values are settings, not tuned on a Nepal test set.
- **What is logged?** SQLite table: time, class, confidence, source (upload or camera), clip time for uploads, snapshot image. Dedupe: each class at most once per 10 s per source, so a standing cow is not logged 300 times. Log page has filters; Stats page shows per class, per hour, last seen, people counted separately.
- **Live performance?** The website runs on CPU by default (config `device: cpu`) and processes every 3rd live frame and every 5th upload frame to keep CPU use low. We have not measured website FPS; the 78 FPS figure is the model alone on the GPU.
- **Privacy?** Server binds to 127.0.0.1, nothing is sent to external services; people are detected only to be excluded from the animal log. Avoid showing faces or licence plates on slides.
- **What if two animals overlap or are in a group?** Group scenes are a known weak spot (missed goats in the crowded test image). Dedupe means the log records the class, not exact headcount.
